How code and the LLM move a case and make the decision: every path

Code runs every step and makes every decision. The model is asked fixed questions at two points and its replies are checked before they count. A person approves only outcomes that post or reject an invoice; holds and escalations post nothing. All files are under src/finagent/.

1 Code moves the run: each step returns the next one; a checkpoint after every step; budgets cap tool and model calls 7 Hold / escalate posts nothing, so there is nothing to approve (never an auto-approval). New evidence or a reviewer's answer starts attempt 2 from RECEIVE (once: the old run becomes SUPERSEDED)
2 No LLM here: parsing, policy search and tool calls are code (permission, timeout, retries, audit) 8 Post or reject always needs a person (no auto-approval): every required approver (by amount / authority); any rejection ends it
3 Code chooses the evidence and the questions; the model picks one allowed answer and quotes the evidence 9 SUBMIT is the only write (deny-by-default, needs the approval, sandbox, idempotent); policy changed since approval, or this invoice already decided by another run → hold
4 Code checks every answer (allowed? quote really there? sure enough?); unsure → warn, ask for evidence or review 10 Any step can fail safe: budget, permission, error, or submit failing after retries → FAILED, nothing posted
5 The narrative is checked by code: schema, citations, numbers; invalid → retry, then a flagged fallback 11 An invalid request never becomes a run (HTTP 422); a repeated Idempotency-Key returns the existing run
6 DECIDE: most cautious outcome wins; the model may escalate, never relax. Policy not matching the verified baseline → hold Blue = code · purple = model · green = person / completed · red = held · grey = not processed. Tags = run status
