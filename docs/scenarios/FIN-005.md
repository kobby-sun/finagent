# FIN-005 — Duplicate approval callback

**Kind:** required  |  **Input format:** CSV export  |  **Policies:** FIN-POL-003 s5, FIN-POL-001 s6

## Signals

The same approval callback is delivered twice, then a late conflicting callback arrives.

## Request

```json
{
  "case_id": "FIN-005",
  "invoice_ref": "EOS-5512",
  "vendor_id": "V-1005",
  "amount": "3300.00",
  "currency": "AUD",
  "po_ref": "PO-40005",
  "requester_id": "u-req-11"
}
```

Attachments: `EOS-5512.csv` (text/csv, source=supplier) — see `mock_data/cases/FIN-005/attachments/`.

## Expected control behaviour

```json
{
  "status": "COMPLETED",
  "outcome": "APPROVE_FOR_POSTING",
  "pool_status": "SUBMITTED",
  "erp_decisions": 1
}
```

## Steps

1. Start run -> expect `AWAITING_APPROVAL`, outcome `APPROVE_FOR_POSTING`
2. `APPROVE` by `u-ccm-01` (callback `cb-fin005-A`) -> HTTP 200, run `COMPLETED`
3. `APPROVE` by `u-ccm-01` (callback `cb-fin005-A`) -> HTTP 200, run `COMPLETED` (replayed response)
4. `APPROVE` by `u-dd-01` (callback `cb-fin005-B`) -> HTTP 409, run `COMPLETED`
5. Check exit_node=FINALIZE, audit_events=['approval.callback_replayed', 'approval.duplicate_ignored:conflict']
6. Assert erp_decisions=1

## Run it

```bash
finagent start --case FIN-005
finagent approvals --status PENDING --explain   # if awaiting approval
finagent approve <approval_id> --approver <user> --callback-id <id>
finagent eval --cases FIN-005
```
